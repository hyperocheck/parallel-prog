# Lab 2

## Task description

Модифицировать программу из л/р №1 для параллельной работы по технологии OpenMP.  Провести серию экспериментов с разным количеством потоков (1, 2, 4, 8 и т.д.), разными размерами матриц (примерно 200, 400, 800, 1200, 1600, 2000), с разным количеством вычислительных ядер при наличии технической возможности (1, 2, 4, 8 и т.д. ), иначе использовать фиксированное существующее количество вычислительных ядер, например 4.


## Files

`matmul.c` - умножение матриц с OpenMP  
`Makefile` - сборка (`-fopenmp`)  
`gen_matrix.py` - генерация случайных матриц  
`verify.py` - верификация результата через NumPy  
`experiments.py` - серия экспериментов (размеры x количество потоков) + график  
`run.sh <n> [threads]` - все разом  

## Device

CPU: Intel(R) Core(TM) i5-8265U @ 1.60GHz, 4 core 8 threads

## Description

Распараллелен внешний цикл `i` в `multiply` директивой `#pragma omp parallel for schedule(static)`: диапазон строк результата `C` заранее делится поровну между потоками `schedule(static)`, каждый поток независимо считает свой непересекающийся блок строк, общих данных при этом нет.

Потоки создает не сам код, а рантайм OpenMP: при входе в `#pragma omp parallel for` главный поток форкает команду воркеров и они уже разбирают между собой итерации цикла, а по выходу из блока ждут друг друга на неявном барьере и сливаются обратно в один поток. Количество потоков задается `omp_set_num_threads()`

## Results 

`time` = замер omp_get_wtime() вокруг вызова multiply()  
`GFLOPS` = 2·N^3 / `time` / 1e9  
`speedup` = `time(threads=1)` / `time(threads=N)` для того же N  
`verify` = сравнение с NumPy (`A @ B`)

## Summary

С ростом числа потоков время выполнения падает, но не линейно: на 8 потоках максимальное ускорение ~3-4x, хотя формально доступно 8 потоков. Причина такая, что у CPU только 4 физических ядра, а остальные 4 потока логические (два логических потока на одно физическое ядро делят одни и те же исполнительные блоки и кэш), поэтому переход с 4 на 8 потоков дает намного меньший прирост, чем с 1 на 4, а на некоторых размерах (N=1200) 8 потоков даже медленнее 4, так сказываются накладные расходы на синхронизацию потоков.
